# 20260825_slice-dd.md
## Slice DD — Codebase Hygiene and Enforceable Quality Gates

> Status: planned.
> This document is an implementation contract.
> It is not completion evidence.

---

## Purpose

Reduce verified code, configuration, dependency, documentation, and test-maintenance debt while preserving JARVISv7's validated runtime behavior. Establish Ruff and mypy as enforceable checks in the existing backend validation path after the behavior-preserving cleanup is complete.

Completion is observable through a smaller supported surface, behavior-focused tests, safe archive extraction, equivalent resolved model-catalog values, and a `validate_backend.py ci` command that rejects lint, type, or test failures.

---

## Implementation Contract

- Preserve existing validated behavior unless this slice explicitly retires an inactive configuration field or obsolete artifact.
- Use existing configuration, extraction, provisioning, test, and validation mechanisms; do not create parallel paths.
- Keep changes limited to the files and behavior named in this slice.
- Add or update focused tests for each changed logic branch or public contract.
- Record validation evidence before governance updates.
- Update `SYSTEM_INVENTORY.md` only after Windows AMD64 and Windows ARM64 evidence exists, unless the user explicitly approves narrower inventory evidence.
- Treat `pyproject.toml` as the dependency source of truth and regenerate `backend/requirements.txt` only through `scripts/provision.py lock`.
- Preserve unknown keys already present in `.env` when the supported operator-setting surface is reduced.
- Apply safe Ruff fixes selectively; do not perform unrelated whole-repository formatting.
- Use precise mypy configuration for optional imports; do not enable global missing-import suppression.
- Follow Python's archive-path inspection guidance for downloaded ZIP files: [Python `zipfile` safety guidance](https://docs.python.org/3/library/zipfile.html).
- Keep development dependencies out of the runtime dependency set: [PyPA dependency groups](https://packaging.python.org/en/latest/specifications/dependency-groups/).
- Prefer behavior-oriented desktop evidence and Rust compilation: [Tauri testing guidance](https://v2.tauri.app/develop/tests/).

## Baseline Consumed

- `scripts/validate_backend.py` already provides profile, unit, integration, regression, runtime, matrix, all, and CI validation commands. This slice extends `ci` with Ruff and mypy. Boundary: existing exit-code meanings remain stable.
- `pyproject.toml` already owns dependencies and Ruff, mypy, pytest, and coverage configuration. This slice removes unused packages and makes the configured quality tools operational. Boundary: hardware-specific runtime packages remain in hardware extras.
- `scripts/provision.py lock` already generates `backend/requirements.txt` from base dependencies. This slice uses that path after dependency changes. Boundary: the generated requirements file is never edited directly.
- `scripts/ensure_models.py` already validates runtime ZIP and TAR member paths before manual extraction. This slice strengthens the ZIP validation contract and reuses it for model ZIP sources. Boundary: valid relative archive layouts and artifact-selection policy remain unchanged.
- `backend/app/core/settings.py` and `backend/app/api/routes/config.py` already define the supported operator-setting surface. This slice removes fields that have no runtime consumer. Boundary: active settings and unknown `.env` keys retain their behavior.
- `desktop/tests/static.test.mjs` already provides source-contract assertions and executable JavaScript behavior checks. This slice makes it the desktop contract authority. Boundary: Rust compilation remains separate `cargo check` evidence.
- `config/models/llm.yaml` already uses YAML anchors for shared Linux AMD64 serve profiles. This slice extends that established pattern to other identical values. Boundary: canonical parsed model values must remain equal.
- `backend/app/runtimes/internetsearch/` already provides SearXNG, DDGS, and Tavily runtimes behind a shared interface. This slice preserves that substrate and its direct tests. Boundary: no normal conversation invocation path is added.
- `SYSTEM_INVENTORY.md` already records that internet-search runtimes lack a normal conversation or agent invocation path. This slice does not promote that capability.

If any consumed baseline is absent when implementation begins, stop and resolve the discrepancy before changing behavior.

## Target Observable Behavior

- `backend\.venv\Scripts\python -m ruff check backend scripts` exits `0` without suppressing behavior-sensitive findings broadly.
- `backend\.venv\Scripts\python -m mypy backend\app` exits `0` in the repository venv without global missing-import suppression.
- `backend\.venv\Scripts\python scripts\validate_backend.py ci` runs Ruff, mypy, unit, integration, and regression validation and propagates failures through documented exit codes.
- Model and runtime ZIP downloads reject traversal, POSIX absolute, Windows drive, UNC, and empty member targets before writing files.
- Valid relative ZIP member paths preserve their archive layout under the configured artifact root.
- `/v1/config` omits and rejects the seven retired inactive settings while preserving active settings and unrelated `.env` content.
- `config/models/llm.yaml` loads to the same canonical model values after anchor consolidation.
- `npm --prefix desktop test` owns desktop JavaScript and source-contract evidence; `cargo check` owns Rust compilation evidence.
- No direct user-facing surface is added; behavior is observable through configuration metadata, validation output, and tests.

## Vocabulary / Contract Terms

- **Unreferenced function**: a function with a repository definition and no production, test, script, or configuration reference.
- **Inactive setting**: an exposed setting that is parsed or displayed but has no runtime consumer.
- **Canonical catalog value**: the recursively loaded value produced by `yaml.safe_load`, independent of YAML anchors or aliases.
- **Desktop contract authority**: the single suite that owns desktop source-boundary and JavaScript behavior assertions.
- **Inventory eligibility**: validation evidence sufficient to update `SYSTEM_INVENTORY.md` under the repository host-class policy.

## Sub-Slice DD.2 — Quality-Gate Restoration

### Goal

Make the existing Ruff and mypy configuration enforceable and connect both tools to the backend CI validation path.

### Scope

Modify:

- `backend/`, `scripts/`, and tests reported by Ruff — apply safe mechanical fixes and manually resolve behavior-sensitive findings.
- `pyproject.toml` — add narrow `E402` per-file exceptions for path-bootstrap scripts, remove mypy's fixed `python_version`, add `types-PyYAML` and `types-psutil` to the dev extra, and add precise optional-module overrides including exact `transformers` imports.
- The 11 mypy-reported application files — clarify optional values, callable contracts, entry types, and mappings without changing runtime decisions.
- `scripts/validate_backend.py` — run Ruff, mypy, unit, integration, and regression checks from `ci` in that order.
- `backend/tests/unit/scripts/test_validate_backend_script.py` — verify command construction, ordering, failure propagation, live-test suppression, and documented exit-code behavior.
- `backend/app/hardware/provisioning.py`, `backend/app/hardware/preflight.py`, and dependency tests — include newly declared type-stub packages in dev-environment expectations.
- `backend/requirements.txt` — regenerate only if base dependency metadata changes further.

Quality-gate rules:

1. Ruff uses `target-version = "py311"` as the minimum syntax contract.
2. Mypy uses the repository venv interpreter and precise optional-import overrides.
3. Quality-command exit `0` maps to PASS; a nonzero tool failure maps to validator failure without running later phases when fail-fast behavior is selected by the existing orchestration contract.
4. Pytest exit `5` retains skipped-not-failed mapping where already documented.
5. Live tests remain excluded from `ci`.

### Ownership Boundaries

- Ruff owns lint and minimum-version syntax checks.
- Mypy owns static type checks for `backend/app`.
- `validate_backend.py` owns backend closeout orchestration and exit semantics.
- Existing unit, integration, regression, runtime, matrix, and all commands retain their established targets.

## Risks and Sequencing Notes

| Risk | Severity | Mitigation |
|---|---|---|
| YAML anchor consolidation changes a resolved profile value | High | Capture and compare canonical parsed values before and after DD.1 |
